# Problems Log — real issues hit, and the exact fix

Every entry here actually happened during this build. Check here first
when something looks wrong before asking — it's probably already solved.

| Symptom | Cause | Fix |
|---|---|---|
| Right panel shows **"Current variant"** with error: *"These layers have invalid names. Make sure that all variant names are of the form: Prop=Value, Prop=Value, ..."* | Current Figma requires the explicit `PropertyName=Value` format for every variant layer name. Bare comma-separated names like `Default, Primary` (which older Figma versions auto-parsed into two properties) are now rejected. | Rename every variant layer to the explicit form, e.g. `State=Default, Style=Primary` instead of `Default, Primary`. Do this **before** combining — all build docs in this folder already use the correct format now. |
| New shape/icon defaults to **black fill**, no rounding, wrong icon (a "person" silhouette) | This is Figma's own **default placeholder content** — it appears whenever you create a frame/component without explicitly setting fill, radius, or swapping the default icon. It is never something to build on top of. | Delete it and rebuild explicitly setting Fill, Corner radius, and swapping any icon (see "Swap instance" in the Button steps) — never assume a default looks right. |
| Corner radius field shows **"Mixed"** with 4 different numbers (e.g. 30/6/6/30) | The 4 corners were set independently instead of linked, OR multiple selected shapes have different values from each other. | Click the **link-all-corners icon** next to the Corner radius field (turns 4 fields into 1), then set/bind that single field. Do this on every shape *before* binding it to a variable. |
| Variant grid shows all 6 button variants in **one long row** instead of a 2×3 grid | Component sets arrange based on where you physically drop each variant, not automatically by property. | Select the variants for one group (e.g. all "Secondary"), drag them as a group, and watch for a **blue horizontal + blue vertical guide** to appear together before releasing — that's the snap point for a new row aligned to existing columns. |
| Bulk **native** Figma variable import creates Number/String variables fine but **silently creates zero Color variables** | Confirmed current limitation of Figma's own native Variables → Import feature — not a mistake in the JSON file. | Use a separate published plugin for colors specifically (we used **"JSON to Color Variables"**, format = Tokens, no wrapper key, plain `value`/`type` not `$value`/`$type`) — see `01-variables.md`. |
| A bulk-import plugin creates far fewer variables than the file contains (e.g. 14 of 43) | The plugin only supports **one level of nesting** — a top-level key whose children are token leaves. A structure like `Colors → Brand → 100` is 2 levels deep and gets silently skipped. | Flatten the JSON so the `/`-separated name is a single key: `"Brand/100": {...}` instead of nesting `"Brand": {"100": {...}}`. |
| "Import plugin from manifest" / "Development" menu item doesn't exist anywhere in the browser, on any menu | This is a **hard Figma platform limitation**, confirmed via Figma's own docs: local/unpublished plugin development requires the **desktop app**, on every plan, with no browser workaround — it is not a Chrome policy, extension, or account issue. | Either use the desktop app for that one specific task, or avoid local dev plugins entirely and use **published** Community plugins instead (those run fine in-browser — this is how the variable-import plugins above worked). |
| Figma MCP (the `use_figma` write tool) throws "reached the Figma MCP tool call limit" | Free/Starter Figma plan caps **all** MCP tool calls (reads AND writes) at **20 per month, total** — confirmed by testing `use_figma` directly, not just the read tools. | No workaround without upgrading the Figma plan. Manual building (this whole `manual-build-steps/` folder) is the free alternative. |
| A duplicated component instance still shows the **old** icon/color after changing the original | You edited the **master component**, but the icon *inside* it was already overridden on an instance-by-instance basis, or you edited a detached copy instead of a real instance. | Check the Layers panel: an instance has a filled diamond icon; a detached copy has a plain shape/frame icon. If it's detached, there's no link to fix — rebuild that one from a fresh instance instead. |
| Pressing `F` and clicking on canvas creates a **full phone-screen-sized frame** (e.g. named "iPhone 17 - 1", 402×874) instead of a small box | `F` shows Figma's device-preset list; clicking near/on it (instead of freehand-dragging) selects a preset size. | Don't delete it — resizing still works fine. Set **Resizing → W → Hug contents** (H is often already Hug) and it'll shrink to fit its contents once you add them. Rename the frame away from the preset name. |
| Text and an icon inside an Auto Layout frame **stack vertically** instead of sitting side by side | Auto Layout's **Flow** defaults to **Vertical**, not Horizontal — it is not automatic based on content. | In the Auto Layout section (near Padding/Gap), find the **Flow** row's icon group and click the one showing horizontal side-by-side lines/arrow instead of the highlighted vertical one. |
| Can't find the "link all corners" icon for Corner radius | It's in a **different section** than Auto Layout — scroll to **"Appearance"** (below Auto Layout, has Opacity + Corner radius together), not inside the Auto Layout section itself. | The icon sits immediately next to the Corner radius number field — a small square with one corner marked. Click it to toggle between 4 separate fields and 1 shared field. |
